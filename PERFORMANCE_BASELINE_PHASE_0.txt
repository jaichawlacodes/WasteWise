Architecture findings confirmed by current source
--------------------------------------------------
- Client routes directly import utils/db/action.ts; that imports Drizzle and Neon through utils/db/dbConfig.jsx.
- next.config.mjs includes DATABASE_URL in its env object.
- Header is globally dynamically loaded with ssr: false and imports/constructs Web3Auth.
- app/page.tsx imports Cobe and Framer Motion and creates a continuous globe loop with mapSamples: 4000.
- app/page.tsx performs three independent database requests sequentially after hydration.
- app/report/page.tsx eagerly calls useJsApiLoader with the Places library and uses StandaloneSearchBox.
- collect, report, and messages import @google/generative-ai client-side.
- collect/report/verify retain uploaded image previews as data URLs/base64 strings.
- Leaflet CSS is imported globally from app/layout.tsx while components/Map.tsx is not connected to an active route in the inspected tree.

Phase 0 decision
----------------
The current build is reproducible and the generated chunks provide sufficient evidence to begin architectural optimization. The largest verified opportunities are server-isolating database/Gemini work, removing Web3Auth from the initial path, deferring Maps, splitting client boundaries, and pausing/defer-loading the home globe.

Do not interpret this baseline as proof of a particular Core Web Vital or a guaranteed percentage improvement. Every later phase must rerun npm run build and compare the route/chunk data above, plus browser measurements if tooling becomes available.
