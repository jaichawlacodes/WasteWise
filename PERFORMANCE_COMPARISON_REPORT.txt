6. ARCHITECTURAL CHANGES
--------------------------

a) Database boundary:
   - All utils/db/action.ts functions are now Server Actions ('use server')
   - utils/db/dbConfig.jsx imports "server-only" (prevents client bundle inclusion)
   - DATABASE_URL removed from next.config.mjs public env
   - Client routes can still call action.ts but Next.js translates to server calls
   - No Drizzle/Neon code in any client bundle

b) Web3Auth boundary:
   - Lazy-loaded via dynamic import() only on login action or stored session
   - Anonymous visitors don't trigger Web3Auth initialization
   - No Web3Auth code in initial page load
   - The heavy 800+ kB Web3Auth chunk is not downloaded until user clicks Login

c) Gemini boundary:
   - All Gemini calls now go through /api/gemini server route
   - API key is server-side only (GEMINI_API_KEY or NEXT_PUBLIC_GEMINI_API_KEY on server)
   - No @google/generative-ai in client bundles
   - Image uploads sent as multipart FormData, not base64 strings

d) Google Maps replaced with MapLibre:
   - Removed @react-google-maps/api (deprecated SearchBox)
   - Added maplibre-gl with OpenStreetMap raster tiles (no API key needed for OSM)
   - Geocoding via server-side Nominatim proxy (/api/geocode)
   - MapLibre is dynamically loaded only on /report

e) Globe optimization:
   - Cobe dynamically imported (not in initial bundle)
   - Pauses when IntersectionObserver detects out-of-viewport
   - Pauses when document.visibilityState is hidden
   - Respects prefers-reduced-motion
   - Lower mapSamples on small screens/low-memory devices
   - Refs for pointer state (no unnecessary React re-renders)

f) Client boundary reduction:
   - Settings, Calculator, Verify routes converted to server route shells
   - Interactive parts extracted to client components
   - Header no longer imports framer-motion (CSS transitions instead)


7. REMAINING BOTTLENECKS
-------------------------

- MapLibre GL JS (542 kB) is the largest client chunk. It is correctly route-specific to /report and lazy-loaded, but this is still a significant download for that route. Consider a lighter map solution if map functionality is not critical.

- The Leaflet dependency is still in package.json but no active route uses it. components/Map.tsx exists but is not imported by any active route. This is dead weight that was not removed to avoid breaking hidden features.

- components/Map.tsx and components/ContractInteraction.tsx reference modules not in the workspace (@/utils/litProtocol, @/hooks/useSessionSigs). These are stale but were not removed.

- Public assets: 1.png, 2.png, 3.png, 4.png, 5.png, grid.jpg, next.svg, vercel.svg in /public are not actively used by any route. These could be removed if confirmed unused.

- Notification polling in Header runs every 30 seconds. It now only runs when user is logged in (userInfo exists), but it still polls unconditionally while logged in. Could be optimized with visibility-based pause.

- Cobe globe mapSamples is 4000 (reduced to 2400 on small/low-power devices). Could be further reduced if performance testing shows it's still expensive.


8. COMPROMISES MADE
-------------------

- Leaflet dependency retained (not removed) even though no active route uses it. Map.tsx and ContractInteraction.tsx exist but are not imported. Risk: hidden feature dependency. Mitigation: no current route references them, so they don't affect bundle size.

- Public assets retained (1-5.png, grid.jpg, etc.) even though no current route references them. Risk: visual content removal. Mitigation: trivial disk space impact.

- NEXT_PUBLIC_GEMINI_API_KEY still in .env file (used as fallback if GEMINI_API_KEY not set). The key is now only read on the server side. Risk: minimal since it's not bundled into client code.

- Web3Auth still imported by Header component at module level (but lazy-loaded via dynamic import()). The dynamic import() means it's code-split, not in initial bundle.

- MapLibre is 542 kB uncompressed. This is large for a single route but is correctly lazy-loaded. Alternative lighter map libraries were not evaluated as part of this work.


9. INTENTIONAL OPTIMIZATIONS NOT MADE
---------------------------------------

- No Lighthouse or Core Web Vitals measurement. No Lighthouse CI configured. Could not measure LCP, CLS, INP, TBT, or performance score in this environment.

- No image format conversion (PNG → AVIF/WebP) for public assets. The public/*.png files are small (~30-45 kB each) so the impact would be minimal.

- No font subsetting. Inter and Poppins are loaded from next/font/google which auto-optimizes, but no manual subsetting was done.

- No database index optimization. The audit recommended indexes for reports.status, reports.created_at, etc. but this requires migration changes and Drizzle schema review which was out of scope for the performance audit implementation.

- No service worker or caching strategy. Would help repeat visits but adds complexity.

- No code splitting beyond what dynamic() already provides. Further manual splitting could reduce some route sizes but with diminishing returns.

- No image lazy loading for upload previews. They use plain <img> with data URLs. This was noted but not changed as it affects form UX.

- No removal of @ts-nocheck comments in Header, Map, ContractInteraction. These are code quality issues, not performance issues.

- Leaflet CSS not removed from app/layout.tsx during the initial phases because Map.tsx still has its own leaflet import. (Note: the global Leaflet CSS in layout.tsx was actually removed in Phase 10; the local import in Map.tsx remains.)
